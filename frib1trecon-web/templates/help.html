Cómo funciona frib1trecon

🔎 Qué hace

Dado un dominio, lanza decenas de búsquedas ("dorks") a través de una instancia propia de SearXNG (nunca scrapea Google directamente, por eso no se arriesga a que te bloqueen la IP), además de comprobaciones directas de DNS/TLS/reputación, para encontrar:

  • Documentos ofimáticos públicos (pdf, xlsx, xls, docx, doc, csv, pptx) — se descargan y se les extraen metadatos (autor, último editor, software, empresa, responsable, fechas, rutas internas filtradas y equipos/servidores internos filtrados en rutas UNC).
  • Ficheros sensibles (sql, log, env, bak), tanto indexados en buscadores como rutas habituales que se comprueban directamente (.env, .git/config, copias de base de datos, phpinfo, paneles) — se comprueba si contienen contraseñas, api keys, claves AWS, claves privadas, etc.
  • Menciones del dominio en Google Drive, Docs, S3, Dropbox, Pastebin, Trello, OneDrive, Notion.
  • Posibles leaks en GitHub, GitLab, Ghostbin, JSFiddle, StackOverflow, directorios abiertos ("index of") y paneles de administración expuestos — verificados en local (patrón de credencial real o URL de panel), no solo por lo que diga el buscador.
  • Emails corporativos mencionados en cualquier página indexada (no solo documentos): contacto, directorios, foros, noticias...
  • Postura DNS/WHOIS (SPF/DKIM/DMARC/DNSSEC/AXFR) y TLS/cabeceras de seguridad — activas siempre, gratis, sin api keys.
  • Empleados en LinkedIn, tecnologías web + CVEs/EOL, typosquatting/domain squatting, fuentes externas (Shodan, buckets cloud, reputación, etc.) y puertos abiertos + versión de cada servicio vía nmap — todas activas por defecto para el informe más completo; se pueden destildar una por una en el formulario.

Al final se calcula un nivel de riesgo general (0-100%) resumiendo todo lo anterior.

▶️ Cómo usarlo

  1. Asegúrate de que SearXNG esté arriba (desde frib1trecon/: ./install.sh o python3 setup_searxng.py).
  2. En la página principal, escribe el dominio objetivo (ej. site.com, sin http:// ni www.).
  3. Por defecto corren todas las categorías; destildá las que no quieras (ej. nmap si el dominio no es tuyo o no tenés autorización para tráfico activo) y pulsa Analizar dominio.
  4. Verás el progreso en vivo: cada dork, cada fichero mientras se descarga/analiza, y avisos en rojo si aparece un posible leak. Es normal que tarde varios minutos — es deliberadamente lento para no levantar bloqueos en los buscadores.
  5. Al terminar, se muestra el nivel de riesgo, las tablas de resultados y los enlaces de descarga (informe.txt, informe.docx, informe.xlsx, resultados.json, resultados.csv...).

🚫 Si una búsqueda de repente da 0 resultados

SearXNG solo trae activados por defecto un par de motores reales (Brave, DuckDuckGo). Si lanzas el mismo dominio muchas veces seguidas en poco tiempo, esos motores pueden quedar "suspendidos" por rate-limit durante un rato, y las búsquedas devuelven 0 resultados aunque el dominio sí tenga contenido indexado. Para solucionarlo: 

cd frib1trecon && sudo docker compose restart searxng

Eso limpia el estado de suspensión (vive solo en memoria del contenedor). frib1trecon ya impone un mínimo de 1.5s entre peticiones para que esto no pase por accidente, pero sigue pasando si escaneas el mismo dominio muy seguido.

⚖️ Uso responsable

Es reconocimiento pasivo: solo consulta contenido ya indexado públicamente o hace comprobaciones estándar (DNS, TLS) que haría cualquier navegador; no ataca al servidor del dominio objetivo. Aun así, úsalo solo contra dominios propios o con autorización, y no bajes los delays ni lances muchos dominios seguidos sin necesidad.
